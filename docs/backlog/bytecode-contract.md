# Общий контракт Go&on — GVM: .albc 1.0 и 2.0

Статус: спецификация для параллельной реализации двух команд. Дата: 20 октября 2026 года. Этот документ определяет передаваемые байты и семантику исполнения; он не утверждает, что текущие исходники компилятора или GVM уже реализуют профиль 2.0.

## 1. Область и совместимость

Профиль 1.0 остаётся процедурным и сохраняет прежние байты, опкоды и поведение. Профиль 2.0 добавляет описание существующих классов Object и три объектные инструкции. Структуры Object / Instance не заменяются новой объектной моделью.

Go&on создаёт файл по этому контракту. GVM выбирает парсер по версии, проверяет файл и только затем исполняет его. Оба профиля имеют flags=0; поддерживаются ровно версии 1.0 и 2.0. Неизвестные major, minor, flags, теги и опкоды отклоняются, не угадываются и не считаются пустыми командами.

Программа с классами или объектными операциями использует 2.0. Процедурную программу можно записывать как 1.0; профиль 2.0 также допускает class_count=0. Объектные секции и команды запрещены в 1.0. Расширение имени файла для обоих профилей — .albc; оно не заменяет проверку заголовка.

Изменения этого контракта синхронно отражаются в бэклоге Go&on. Пока существующая документация и Opcode.kt компилятора содержат только v1, они служат описанием реализованного v1, но не отменяют спецификацию 2.0 здесь.

## 2. Числа, строки и индексы

- u8 — один байт, u16 — два, u32 — четыре. Все многобайтовые числа big-endian; padding и выравнивания нет.
- i32 — четыре байта дополнительного кода. Внутренние usize, указатели, enum-size, sizeof и MemoryBlock не сериализуются.
- Индексы начинаются с 0. Количество u16 допускает 0..65535 элементов; при максимальном количестве последний индекс равен 65534, а не 65535.
- Строка — корректный UTF-8 по RFC 3629, без внутреннего NUL, не более 1048576 байт. Длина в байтах; терминатор в файл не записывается. Пустая строка допустима как значение.
- Все имена классов и полей непусты и состоят из допустимых символов идентификатора Go&on `[A-Za-z_][A-Za-z0-9_]*`. Отладочное имя функции — String по общему строковому контракту, может содержать точку; дополнительных ограничений имени функции в профиль 1.0 не вводится.
- Имена классов уникальны по байтам UTF-8. Имена полей уникальны внутри класса. Индексы функций-методов не повторяются ни внутри списка, ни у разных классов; наследование и совместное владение одним методом не вводятся.
- Имена и обычные String-константы хранятся в одном пуле; имена входят в его общий предел. Дедупликация допустима.

## 3. Заголовок и порядок секций

Header всегда занимает 12 байт:

| Смещение | Поле | Тип | Значение |
| --- | --- | --- | --- |
| 0 | magic | bytes[4] | 41 4C 42 43, ASCII ALBC. |
| 4 | version_major | u16 | 1 либо 2. |
| 6 | version_minor | u16 | 0. |
| 8 | flags | u16 | 0. |
| 10 | entry_function_idx | u16 | Индекс функции запуска. |

```text
1.0: Header -> ConstantPool -> FunctionTable -> CodeSection -> EOF
2.0: Header -> ConstantPool -> FunctionTable -> ClassTable -> CodeSection -> EOF
```

Указателей на секции в заголовке нет. Загрузчик проходит записи по их точным длинам. code_offset функций не меняется из-за вставки ClassTable: он отсчитывается от code_bytes, а не от файла.

## 4. ConstantPool: одинаковый в 1.0 и 2.0

```text
constant_count: u16
repeat constant_count:
  tag: u8
  payload:
    tag 1: value:i32
    tag 2: value:u8, только 0=false или 1=true
    tag 3: length:u32, bytes[length]:UTF-8
```

Тегов констант 0 и 4 нет. В пул не записываются NULL, живой экземпляр, указатель или описание класса. Тег типа Bool равен 2; значение false/true равно 0/1 — это разные поля.

Загрузчик явно переводит файловые теги в VALUE_INT / VALUE_BOOL / VALUE_STR. Эскиз внутреннего ValueType перечисляет NULL, INT, BOOL, STR, OBJ; его порядок и размер не заменяют правила чтения файла.

## 5. FunctionTable: одинаковая запись в двух профилях

```text
function_count: u16, от 1 до 65535
repeat function_count:              // запись ровно 12 байт
  name_const_idx: u16               // существующая String-константа
  param_count: u8
  local_count: u8
  code_offset: u32
  code_length: u32
```

Индекс функции равен позиции записи. param_count <= local_count <=255. Длина кода положительна. Первый code_offset=0, каждый следующий равен концу предыдущей функции, последний конец равен code_size. Разрывов, наложений и независимых областей кода нет.

Функции верхнего уровня, методы и сформированные компилятором функции инициализации используют одну таблицу и обычный CALL. Отдельных записей Method с полной сигнатурой, флагов конструктора и динамической таблицы виртуальности нет.

У метода и функции инициализации this — неявный параметр 0; явные параметры занимают слоты 1..N. This входит в оба счётчика. Поэтому явных параметров не более 254, а локальные и скрытые временные слоты тоже должны поместиться в local_count.

В 2.0 entry_function_idx должен указывать на функцию с param_count=0, не указанную в списках методов. Сравнение её отладочного имени с main загрузчику не требуется. В стандартном режиме Go&on выбирает main; раннер запускает без аргументов. В 1.0 сохраняется прежняя проверка: валидный индекс при загрузке, совпадение числа аргументов при context_start.

## 6. ClassTable: только 2.0

```text
class_count: u16
repeat class_count:                  // номер записи = class_index
  name_const_idx: u16                // имя класса: String-константа
  field_count: u16
  repeat field_count:                // поле: ровно 5 байт
    name_const_idx: u16              // имя поля: String-константа
    type_tag: u8
    type_class_idx: u16
  method_count: u16
  repeat method_count:
    function_idx: u16                // индекс общей таблицы функций
```

Длина записи класса равна `6 + 5*field_count + 2*method_count` байтам. Длина всей ClassTable — 2 плюс сумма длин записей. Пустой класс и класс без методов допустимы. class_count=0 занимает ровно два нулевых байта.

Индекс класса соответствует Object.objIdx. Порядок полей соответствует Object.types и Instance.data. method_count / function_idx соответствуют Object.functionCount / Object.funcIdx. Это сериализация уже описанной модели GVM, а не ещё один вид экземпляра.

Для каждой функции из method list обязательно param_count>=1. Функция не принадлежит нескольким классам. Имена методов отдельно не дублируются: функцию выбирает компилятор по своим символам, в файле остаётся её индекс. Полное отладочное имя можно формировать как Class.method, но исполнение не ищет метод по этой строке.

Функция инициализации не обязана и не должна автоматически включаться в список обычных методов: это служебная функция общей таблицы, напрямую вызываемая сгенерированным кодом. Для создания используется индекс известной компилятору функции; запись initializer_idx в ClassTable не нужна. Перегрузки конструкторов, если они приняты языком, разрешаются компилятором до записи CALL и не требуют нового поля загрузчика.

### 6.1 Теги объявленного типа поля

| type_tag | Объявленный тип | type_class_idx |
| --- | --- | --- |
| 1 | Int | Ровно 0xFFFF. |
| 2 | Bool | Ровно 0xFFFF. |
| 3 | String | Ровно 0xFFFF. |
| 4 | Экземпляр конкретного класса | Валидный индекс меньше class_count, не 0xFFFF. |

Пара type_tag + type_class_idx всегда занимает 3 байта, в том числе у встроенных типов. 0xFFFF свободен от валидных class_index при class_count<=65535. Неканоническая пара, tag=0 или неизвестный tag отклоняются. Отсутствие результата функции и служебный NULL не являются типами полей.

Теги 1/2/3 сохраняют знакомые обозначения типов, но таблица типов полей и таблица тегов констант — разные контексты: 4 допустим только в записи типа поля, не в ConstantPool. Номер 4 теперь закреплён именно этим файловым контрактом, а не получен неявным cast внутреннего enum.

Все ссылки на классы, в том числе вперёд и циклические, разрешаются после создания стабильных Object для всей таблицы. Для примитивов FieldType.object=NULL; для tag=4 — адрес соответствующего Object той же программы.

### 6.2 Хранение имён и неизменяемость

class name_const_idx проверяется при загрузке и хранится в staging для диагностики; добавлять имя в Object.literal не нужно: literal остаётся NULL и не владеет строкой. Для поля program_set_field создаёт собственную учтённую копию String через libstr. Нельзя копировать владеющий дескриптор из константы присваиванием.

Флагов val/var, видимости и accessor в файле нет. Ограничения исходного языка обеспечивает компилятор. Verifier не обещает доказать запрет изменения val в произвольно подделанном байткоде. NULL и nullable-типы этим контрактом не добавляются в язык.

## 7. CodeSection и инструкции

```text
code_size: u32
code_bytes: bytes[code_size]
EOF immediately after code_bytes
```

### 7.1 Сохранённые инструкции

Опкоды 0x01–0x19 действуют в обоих профилях без изменения:

| Код | Имя | Операнды | Длина | Требуется / эффект высоты |
| --- | --- | --- | --- | --- |
| 01 | LOAD_CONST | u16 constant_idx | 3 | 0; h+1. |
| 02 | LOAD_LOCAL | u8 slot | 2 | 0; h+1. |
| 03 | STORE_LOCAL | u8 slot | 2 | 1; h-1. |
| 04–08 | ADD, SUB, MUL, DIV, MOD | Нет | 1 | 2; h-1. |
| 09 | NEG | Нет | 1 | 1; h. |
| 0A | CONCAT | Нет | 1 | 2; h-1. |
| 0B–10 | CMP_EQ, CMP_NE, CMP_LT, CMP_GT, CMP_LE, CMP_GE | Нет | 1 | 2; h-1. |
| 11 | NOT | Нет | 1 | 1; h. |
| 12 | JUMP | u32 function_local_target | 5 | 0; h, только target. |
| 13 | JUMP_IF_FALSE | u32 function_local_target | 5 | 1; h-1, target и next. |
| 14 | CALL | u16 function_idx | 3 | param_count; h-param_count+return_arity. |
| 15 | RETURN | Нет | 1 | Ровно 1, терминальная. |
| 16 | RETURN_VOID | Нет | 1 | Ровно 0, терминальная. |
| 17–19 | PRINT, PRINTLN, POP | Нет | 1 | 1; h-1. |

Коды в таблице шестнадцатеричные. Арифметика — i32 с wraparound modulo 2^32; DIV/MOD на ноль — ошибка. Сравнения порядка — Int. CMP_EQ/NE — одинаковые Int/Bool по значению или String по тексту, не объектные ссылки. PRINT/PRINTLN — только Int/Bool/String; POP снимает Value без ручного удаления экземпляра. AND/OR разворачиваются в short-circuit переходы.

### 7.2 Три новые инструкции: только 2.0

Верх стека справа. Нижележащий префикс сохраняется.

| Код | Имя | Операнды big-endian | Длина | Стек | Высота |
| --- | --- | --- | --- | --- | --- |
| 40 | ALLOC_OBJECT | class_idx:u16 | 3 | `[] -> [object]` | 0; h+1. |
| 41 | GET_FIELD | class_idx:u16, field_idx:u16 | 5 | `[receiver] -> [value]` | 1; h. |
| 42 | SET_FIELD | class_idx:u16, field_idx:u16 | 5 | `[receiver, value] -> []` | 2; h-2. |

0x43 и далее не назначены и отклоняются. Ни CALL_METHOD, ни DUP, ни OBJ_EQ, ни отдельного опкода конструктора нет. В 1.0 коды 0x40–0x42 отклоняются даже при недостижимости.

### 7.3 ALLOC_OBJECT

Проверить профиль, class_idx, доступность описания, ресурсные пределы и возможность push; reserve до выделения экземпляра. Под защитой текущей инструкции вызвать instance_create_object, получить OBJ и установить его на стек до возобновления GC. Instance содержит фиксированный массив служебных NULL; пользовательская инициализация не исполняется этой инструкцией.

Не снимать аргументы конструктора, если они уже лежат ниже: ALLOC_OBJECT всегда добавляет одну ссылку. При неудаче успешного push и продвижения IP нет; частичные ресурсы принадлежат существующему механизму отката / cleanup GVM, а не «исчезают» из учёта.

### 7.4 GET_FIELD

Проверить индексы, наличие receiver, OBJ-тег и принадлежность приложению; receiver.object должен точно равняться program.objects[class_idx]. Проверить field_idx по этому классу. Прочитать Value и проверить его соответствие объявленному типу и приложению. Служебный NULL даёт EXECUTION_FAULT_KIND_UNINITIALIZED и CORE_INVALID_STATE; это не значение по умолчанию.

После проверок заменить верхнюю ссылку копией значения поля, не изменяя высоту. При ошибке исходный стек сохраняется. Новая дочерняя ссылка должна оказаться на стеке до снятия защиты от GC; чтение не копирует экземпляр.

### 7.5 SET_FIELD

Вершина — новое значение, следующий элемент — receiver. Проверить оба значения и индексы до изменения: точный класс receiver, допустимый слот, тип поля и принадлежность ссылок приложению. NULL не совпадает с объявленным типом. После успешного instance_set_field снять ровно два значения и продвинуть IP. Результата нет.

При проверочной ошибке стек и прежнее поле сохраняются. Замена ссылки не удаляет прежний экземпляр, не вызывает деструктор и не выполняет рекурсивный free. Сборщик позже определит его достижимость.

### 7.6 Ошибки исполнения и атомарность

Неверная структура инструкции / индекс — fault BYTECODE; нехватка операндов — STACK; несовпадение тега или класса — TYPE; незаполненное поле — UNINITIALIZED; ресурсный предел — LIMIT; отказ выделения — MEMORY. ErrorCode остаётся кодом PUNos; классификация не перенумеровывает его.

Вся инструкция выполняется под сбалансированной паузой GC, с подготовкой до commit. Ссылки из произвольного C-стека не считаются корнями. Это правило отдельной инструкции, не запрет сборки на всё время пользовательского конструктора.

## 8. Методы и инициализация через обычный CALL

Для метода компилятор вычисляет receiver первым один раз и сохраняет его в скрытом локальном слоте, затем вычисляет явные аргументы справа налево. Перед CALL загружает сохранённый receiver последним:

```text
... argN ... arg2 arg1 this       // this на вершине
pop -> slot 0 = this
pop -> slot 1 = arg1
```

Получатель записи поля вычисляется один раз раньше правой части. Обычные функции сохраняют прежний обратный порядок аргументов. Скрытые слоты учитываются в local_count и не затираются вложенными вычислениями, пока значение нужно.

Функция инициализации — обычная функция без результата с this в slot 0 и RETURN_VOID. Нет специальной runtime-роли или таблицы вызовов конструктора. Для создания с двумя параметрами Go&on генерирует:

```text
<arg2>
<arg1>
ALLOC_OBJECT class_idx
STORE_LOCAL temp
LOAD_LOCAL temp
CALL initializer_function_idx
LOAD_LOCAL temp
```

После CALL значение не возвращается; последняя загрузка даёт единственную ссылку как результат создания. Пока исполняется инициализация, экземпляр удерживается временным слотом вызывающего и this вызываемого. GC и порции исполнения между инструкциями разрешены.

Компилятор проверяет заполнение обязательных полей на всех успешных путях, запрещает чтение незаполненного и раскрытие недостроенного this наружу. Инициализаторы полей включаются в функцию инициализации по правилам языка. Не требуется объявлять все поля параметрами заголовка. При отказе конструктора успешного результата создания нет; уже выполненные побочные эффекты не откатываются автоматически.

## 9. Проверки загрузки и исполнения

### 9.1 До публикации

Проверить всю раскладку, количества, имена, объявленные типы полей, индексы, точный EOF, диапазоны кода и уникальность funcIdx среди class methods. В 1.0 objectCount=0; в 2.0 objectCount=class_count<=65535. Не использовать недостижимость для разрешения неизвестной команды или неверного индекса.

Линейно декодировать каждую функцию, в том числе недостижимые инструкции; цели JUMP обязаны совпадать с началом инструкции своей функции и быть строго меньше code_length. Проверить все слоты и операнды, новые class_idx / field_idx — по таблице классов. Объектные инструкции имеют ту же длину 3 / 5 байтов независимо от значения индекса.

Арность вызова выводится из RETURN / RETURN_VOID, как в 1.0; смешение запрещено. Полные типы параметров / результата функции в файл не добавлены. CFG начинается с высоты 0, требует одинаковой высоты на join, отсутствия underflow и falloff и точной высоты у возврата. Новые эффекты перечислены выше.

Этот verifier не доказывает тип каждого промежуточного значения, запрет изменения val и полную инициализацию полей исходной программы. Их обеспечивает Go&on, а динамические GET/SET защищают GVM от несовместимых и незаполненных значений.

### 9.2 Ресурсные пределы

Константы, функции, классы, поля одного класса и методы одного класса ограничены полями количества u16. Параметры / local_count — u8. Общие суммы полей, размеры staging и произведения считаются в проверяемом usize, не в u16. В одном файле суммарно может быть существенно больше 65535 полей разных классов.

Дополнительно действуют настраиваемые maxFileBytes, maxCodeBytes, maxObjects, maxFieldsPerObject, maxMethodsPerObject, maxMetadataBytes и лимиты verifier / исполнения. Эти настройки могут быть строже формата; фиксированные произвольные значения не назначаются. maxObjects=0 разрешает только class_count=0, а не отключает поддержку профиля 2.0.

JVM-компилятор может иметь более строгий предел размеров массивов, чем u32. Тогда он явно отклоняет превышение, не оборачивает сумму и не усекает число при writeShort / writeByte.

## 10. Загрузка и владение

Первый проход по стабильному буферу проверяет весь layout, размеры и суммы без публикации экземпляров. Для 2.0 ClassTable читается до code_size; для 1.0 этот шаг отсутствует. До любого выделения проверяются длины и ресурсные пределы.

При построении модели сначала выделяются все стабильные Object через существующий program_allocate. Затем program_prepare_object создаёт массивы каждого класса. Лишь после этого FieldType.object разрешается по индексу, и program_set_field создаёт учтённую копию имени. Методы заполняются индексами функций. Прямые и циклические ссылки метаданных не требуют рекурсивного владения или рекурсивного создания.

class name_const_idx и сведения исходных записей нужны загрузчику / verifier для проверки имён и диагностики, но не обязаны храниться в Object после проверки. Object.literal остаётся NULL. Отдельная запись initializer_idx не нужна: CALL уже содержит индекс.

Пул строк — корни приложения после публикации. Во время построения новая программа и все создаваемые строки защищены загрузчиком; ни один частичный результат не становится исполняемым. При ошибке сначала очищаются зависящие экземпляры, затем их метаданные; сохранённые MemoryBlock допускают retry. Ошибка cleanup не затирает первичную.

## 11. Эталонный пример с инициализацией и методом

Намерение программы: создать Counter с полем value=7, вызвать get и вернуть Int 7. Синтаксис конструктора языка здесь не назначается. Зафиксирован следующий порядок констант:

## 12. Приёмочные проверки двух команд

Положительные: эталон возвращает 7; несколько экземпляров независимы; alias сохраняет одну идентичность; вложенные объектные поля имеют точные типы; возврат объекта переживает кадр; receiver-first и обратный порядок аргументов наблюдаются по побочным эффектам; временные ссылки переживают GC и ожидание между инструкциями конструктора.

Отрицательные при загрузке: неизвестная версия / minor / flags, обрезанные секции, неверный type_tag или sentinel, неверный класс / поле / метод, повторный владелец метода, method.param_count=0, неверный entry 2.0, неизвестный хвост, неверная цель перехода, underflow / join / возврат. Дубликаты имён классов / полей и строки вне контракта отвергаются.

Отрицательные при исполнении: чужой класс receiver, несовместимый тип SET, NULL при GET, недостаток памяти ALLOC, ссылка другого приложения в нативной тестовой фикстуре. Ошибка не меняет проверяемое старое поле / стек до commit и не теряет ресурсы.

Проверки должны читать реальные байты. Round-trip через один и тот же reader / writer недостаточен: независимые ожидания размеров, offset и операндов обязательны. Языковые исходники, бинарный разбор и фактический запуск отмечаются отдельными результатами.
