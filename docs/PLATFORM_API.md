# Каталог платформенных функций

[`platform-api.json`](../platform-api.json) — единый машиночитаемый список
предлагаемых платформенных функций для компилятора Gon&On и GVM. Он описывает
21 функцию из документа «Что нужно добавить в Gon&On, GVM и PUNos»:
окна и ввод, сеть, камеру и координаты, постоянные файлы и работу с текстом.

Каталог имеет статус `draft`: сигнатуры подготовлены для согласования с
командами GVM и PUNos. Компилятор загружает каталог из ресурса JAR,
проверяет аргументы и типы результатов и генерирует отдельные инструкции
профиля `.albc` 3.0. Обычные программы сохраняют профили 1.0/2.0.
Реализация runtime 3.0 в GVM и платформенных адаптеров остаётся внешней задачей.

Предлагаемые определения типов, отдельных инструкций платформенных вызовов,
событий, ошибок и границы ответственности трёх проектов описаны в
[`PLATFORM_CONTRACT.md`](PLATFORM_CONTRACT.md). Это отдельный черновик для
согласования; его профиль `.albc` 3.0 реализован на стороне компилятора. Сигнатуры 21 функции
в текущем каталоге сохранены.

## Формат

Файл — JSON в UTF-8. Для чтения подходит стандартная JSON-библиотека;
дополнительные зависимости и переменные окружения не требуются.

| Поле | Назначение |
|---|---|
| `schemaVersion` | Версия структуры JSON, сейчас `2`. Это не версия `.albc`. |
| `status` | Статус согласования каталога, сейчас `draft`. |
| `functions` | Список описаний функций. |
| `functions[].name` | Уникальное имя функции в исходном коде Gon&On. |
| `functions[].description` | Обязательное непустое описание на русском языке: что делает функция и какие данные возвращает, если они есть. |
| `functions[].group` | Тематическая группа; не часть имени или сигнатуры. |
| `functions[].parameters` | Параметры в порядке записи при вызове; `[]` для функций без аргументов. |
| `parameters[].name` | Имя параметра, уникальное внутри одной функции. |
| `parameters[].type` | Имя типа параметра. |
| `functions[].returnType` | Имя типа результата. |

В версии структуры `2` у каждой функции добавлено поле `description`.
Оно предназначено для людей и не участвует в сигнатуре функции.

Например, запись `openWindow` описывает сигнатуру:

```text
openWindow(title: String): WindowResult
```

Позиция функции в списке не является её идентификатором в байткоде.
Порядок параметров описывает исходную сигнатуру, а не порядок значений
на стеке GVM. Каталог не задаёт опкоды, таблицу импортов или соглашение
о вызове C-функций.

## Группы и типы

| Группа | Назначение |
|---|---|
| `window` | Окно, элементы ввода, текст, изображение и метки. |
| `network` | Прослушивание порта, соединения и отправка текста. |
| `device` | Снимок, отправка снимка, координаты устройства и освобождение снимка. |
| `storage` | Чтение и запись текстовых файлов приложения. |
| `text` | Преобразование целых чисел и извлечение поля из текста. |

В сигнатурах используются существующие `Int` и `String`, а также предлагаемые
типы ссылок `WindowRef`, `ListenerRef`, `ConnectionRef`, `PhotoRef` и результатов
`Status`, `WindowResult`, `ListenerResult`, `ConnectionResult`, `PhotoResult`,
`LocationResult`, `TextResult`, `IntResult`. Запись имени типа в каталоге
поддерживается встроенными объявлениями `platform/PlatformAbi.kt` в профиле 3.0.

По исходному предложению объекты результатов должны содержать `ok: Bool`,
`errorCode: Int`, `errorMessage: String` и, при наличии данных, типизированное
поле `value`. Конкретные определения типов, их представление в GVM и отказ
при чтении `value` ошибочного результата предложены в
[`PLATFORM_CONTRACT.md`, §4 и §6](PLATFORM_CONTRACT.md); они ещё требуют
согласования.

В исходном предложении часть типов параметров указана неявно. Для полноты
сигнатур в этом черновике приняты следующие варианты:

- `title`, `text`, `label`, `asset`, `url` — `String`; `asset` обозначает имя
  ресурса изображения приложения.
- `window` — `WindowRef`, `photo` — `PhotoRef`.
- ID элементов `id` и координаты метки `x`, `y` — `Int`.

Эти уточнения также требуют согласования. Контракт предлагает для
`LocationResult` координаты WGS84 в миллионных долях градуса; координаты
метки `drawMarker` относятся к рисованию в окне. Это разные системы координат.

`print` и `println` сохраняют существующую специальную обработку компилятором.
`bindAppState` и обработчики событий относятся к отдельному контракту привязки
состояния и событий и в этот каталог операций не включены.

## Изменение каталога

1. Добавить запись в `functions`, указав уникальное имя, понятное описание
   `description` на русском языке, группу, параметры в порядке вызова и тип
   результата. Имена функций, параметров и типов
   записывать как идентификаторы Gon&On.
2. При введении нового типа описать его назначение и согласовать его
   поддержку с GVM. Изменение имени, порядка или типа аргументов и результата
   существующей функции также требует согласования затронутых команд
   Gon&On, GVM и PUNos.
3. При изменении структуры JSON обновить `schemaVersion` и эту документацию.
4. Проверить синтаксис JSON и выполнить тесты проекта:

   ```bash
   python3 -m json.tool platform-api.json > /dev/null
   ./gradlew test
   ```

Каталог проверяется строго: версия схемы, набор операций с назначенными опкодами,
уникальность имён, допустимые типы и обязательные описания. Новую функцию нужно
одновременно добавить в `PlatformAbi.instructions`, `Opcode`, `Instruction`,
reader/writer/disassembler и контракт. Сигнатуры и арность читаются из JSON.

После изменения JSON пересоберите дистрибутив через `./gradlew installDist`.
Ошибка `UNDEFINED_FUNCTION` для известной операции обычно означает запуск
старого дистрибутива. Вручную копировать JSON рядом с исполняемым скриптом не нужно.
